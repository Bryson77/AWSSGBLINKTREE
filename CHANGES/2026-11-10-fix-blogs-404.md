## 1. Root Causes Identified

The blogs feature returned a 404 (or failed to render published articles) due to **four compounding issues** in how `apps/web` combined Next.js static export (`output: "export"`) with Cloudflare Pages' SPA fallback (`/* /index.html 200`):

1. **Hardcoded `generateStaticParams` in `/blog/[slug]/page.tsx`:**
   - `apps/web/src/app/blog/[slug]/page.tsx` hardcoded `return [{ slug: "welcome" }];` and never queried `public.posts` in Supabase.
   - Meanwhile, `apps/web/src/app/blog/page.tsx` fetched published posts from Supabase on the client and linked every article card to `/blog/${post.slug}`. None of those `/blog/<slug>` routes existed in `apps/web/out/blog/`.

2. **Missing Uppercase Org Slugs & Runtime-Published Articles in `/[org]/blog/[slug]/page.tsx`:**
   - `apps/web/src/app/[org]/blog/[slug]/page.tsx` only generated lowercase `org.slug.toLowerCase()` parameters (`tut`), whereas `apps/web/src/app/[org]/page.tsx` and `apps/web/src/app/[org]/blog/page.tsx` generated both lowercase (`tut`) and uppercase (`TUT`) routes, and the TUT link hub in `public.links` points to `https://awssbg.online/TUT/blog`.
   - Furthermore, the two published TUT articles in `public.posts` (`from-ideas-to-impact-building-personal-portfolios-with-kiro-at-tut` and `preparing-for-the-cloud-aws-certified-cloud-practitioner-mock-examination-at-tut`) were published via the Admin CMS after the last static build, so `apps/web/out/tut/blog/` only contained `welcome.html`.

3. **Incomplete SPA Fallback Router in `apps/web/src/app/page.tsx` & `Header.tsx`:**
   - `apps/web/public/_redirects` rewrites all un-exported URLs (`/* /index.html 200`) to `apps/web/src/app/page.tsx`.
   - `page.tsx` previously inspected only the first path segment (`window.location.pathname.replace(/^\/|\/$/g, "").split("/")[0]`):
     - Visiting `/blogs` (plural) matched `firstSegment = "blogs"`, which was missing from `KNOWN_STATIC_ROUTES`, causing `page.tsx` to render `<OrgHomeClient initialSlug="blogs" />` and display `404 // SBG_NOT_FOUND`.
     - Visiting `/<org>/blog/<slug>` for any article published after the last build matched `firstSegment = "<org>"` and rendered `<OrgHomeClient />` (the institution link hub) instead of `<OrgBlogPostClient />`.
     - Visiting `/blog/<slug>` matched `firstSegment = "blog"` (which was in `KNOWN_STATIC_ROUTES`) and rendered the root SBG directory instead of `<BlogPostClient />`.

4. **`useParams()` Returning Empty Params Under SPA Rewrite & Next.js `<Link>` Fetching Missing `.txt` RSC Payloads:**
   - `BlogPostClient.tsx`, `OrgBlogClient.tsx`, and `OrgBlogPostClient.tsx` relied exclusively on `useParams()`, which returns `{}` when `index.html` is served via Cloudflare Pages rewrite.
   - Article cards in `apps/web/src/app/blog/page.tsx` and `apps/web/src/app/[org]/blog/OrgBlogClient.tsx` used Next.js `<Link>`, which attempts to fetch `.txt` RSC flight payloads that do not exist on disk for articles published via the Admin CMS after a static build.

## 3. Architecture Decision & Why This Solution Is Best

- **Why hybrid pre-rendering + full multi-segment SPA fallback beats build-only static params:**
  - Because `apps/web` uses `output: "export"` on Cloudflare Pages while campus leaders publish new articles at runtime via `admin.awssbg.online`, relying solely on build-time `generateStaticParams()` would mean every newly published blog post would 404 until a developer manually rebuilt and redeployed `apps/web`.
  - By combining build-time `generateStaticParams()` (for fast static HTML delivery of existing posts across both lowercase and uppercase org slugs) with full multi-segment path routing in `page.tsx` and `window.location.pathname` resolution in `BlogPostClient` / `OrgBlogPostClient`, **both** pre-rendered articles and brand-new articles published in the Admin CMS work immediately with zero rebuild required.
